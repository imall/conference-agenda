# conference-agenda-viewer

## 狀態
approved

## 類型
新功能

## 為什麼做
參加研討會時，目前是把要聽的場次手抄成純文字（時間、會議室、標題），現場要一直翻找「現在幾點、下一場在哪間」。希望有一個網頁，可以**直接在網頁上自己新增、編輯、刪除**研討會與場次，在電腦上排好，手機打開就看得到，並隨時間直接告訴我下一場去哪。資料不能寫死在程式裡。

第一個使用案例是 HWDC 2026（https://hwdc.ithome.com.tw/2026/agenda），第一天 2026-10-14 已選 5 場，作為初始資料；之後的研討會都在網頁上自己建。

## 要改什麼
新專案 `D:\repo\conference-agenda`：純靜態網頁（單檔 `index.html` 含 CSS/JS，不用框架、不用建置工具），部署到 GitHub Pages；資料存在使用者指定的 Supabase 專案 `ypnpprbkhalhblfonpai`（使用者決定直接建在這裡，不再確認是否與其他專案共用）。

**資料**
- 唯一的正式資料來源是 Supabase 資料表 `conferences`：一列一個研討會，欄位有 `owner`（預設 `auth.uid()`）、名稱、官網連結、`sessions`（jsonb 陣列，每場有日期、開始/結束時間、會議室、標題、講者、類型）。
- 開啟 RLS：只有 `owner = auth.uid()` 的本人能讀、寫、刪。
- `setup.sql`（預估）：建表＋RLS，以及 HWDC 2026 第一天 5 場的種子資料（指定給最近一次登入的使用者）。在 Supabase SQL Editor 手動執行，可重跑。
- 新增 `catalog` 欄位（jsonb 陣列，格式同 `sessions`）：存放從官網匯入的**全部**場次，作為挑選來源；`sessions` 仍只放「我要去的」場次。`setup.sql` 以 `ADD COLUMN IF NOT EXISTS` 補上，可重跑。
- Supabase URL 與 anon key 直接寫在 `index.html`：anon key 本來就是公開用的，靠 RLS 保護資料。
- 存檔：一次更新整個研討會那一列；Supabase 回成功才算存檔完成。失敗時表單內容保留在畫面上並顯示錯誤，不會清掉。

**登入**
- Supabase Email 魔法連結（輸入 email → 收信點連結）。登入狀態由 supabase-js 保存在該裝置，之後不用再登入。
- 每台裝置第一次要登入一次。

**離線**
- 每次成功讀取後把資料快取到本機（localStorage）。開啟時先顯示快取，再向 Supabase 取最新版。
- 會場沒網路、或 Supabase 免費專案因閒置被暫停時，照樣顯示上次的資料，並標示「離線資料」。

**畫面**
- 手機優先，依日期分組列出場次。
- 頂部「現在／下一場」卡片：進行中與下一場的時間、會議室、標題，每分鐘自動更新；已結束的場次淡化。
- 多個研討會時用下拉選單切換，預設顯示日期最接近今天的研討會。
- 編輯模式：新增／編輯／刪除研討會與場次的表單（刪除需確認）。
- 網址加 `?now=2026-10-14T15:20` 可模擬時間，方便驗證。

**匯入官方議程並挑選**（修訂新增：手動逐欄填表太麻煩）
- 匯入：編輯模式按「匯入官方議程」→ 在電腦上打開官網議程頁，Ctrl+A、Ctrl+C 整頁複製 → 貼進文字框 → 解析出每一場的日期、時間、會議室、類型、標題、講者 → 顯示「解析到 N 場」預覽後存進 `catalog`。同一天再貼一次會取代那天的資料，所以多天議程可以一天一天貼。
- 解析規則以 iThome 研討會頁面格式為準（一行會議室 → 一行「HH:MM - HH:MM 類型」→ 一行標題 → 講者；日期取自「10/14(三)」這類行，年份用研討會場次已知的年份或今年）。其他網站格式不同可能解析不到，仍可用「＋ 場次」手動新增；常用的網站遇到時再加一組解析規則（使用者決定：不做 AI 解析或通用規則）。
- 挑選：「挑選場次」畫面依日期、時段列出 `catalog` 全部場次，同時段的平行場次排在一起；每場一個按鈕，點「＋」加入我的議程、點「✓」移除。與已選場次時間重疊的標示「撞場」。
- 用「點一下加入」而不是拖拉：手機上拖拉容易誤觸、也難捲動，點按更可靠。
- **時間軸檢視**（第二次修訂：清單看不出哪些場次在時間上重疊）：「挑選場次」改成直向時間軸，像日曆的日檢視。一次顯示一天，上方切換日期；縱軸是時間（左側固定時間刻度，每 30 分鐘一條線），每間會議室一欄（欄頭固定），每場是依開始／結束時間定位、高度與長度成比例的方塊，方塊內顯示標題與講者。會議室欄位多於螢幕寬度時，在時間軸區塊內左右滑動（整頁不會橫向捲動）。點方塊加入／移除；已選的方塊實心並打勾。原本的清單檢視由時間軸取代。
- **撞場只標在已選場次**（第三次修訂：未選的方塊被淡化、標記，畫面太雜）：只有「已選」且和另一個「已選」場次時間重疊的方塊才顯示「撞場」；未選的方塊一律正常顯示，不淡化、不標記。
- **登出移進編輯模式**（第四次修訂：登出按鈕在下拉選單旁，容易誤觸）：頂部只留「編輯」；「登出」移到編輯模式工具列最後面，按下要再確認一次（提示登出會清掉這台裝置的離線資料）。「＋ 場次」手動新增保留不動。
- **時間軸放大**（第五次修訂：方塊太小、字 12px，大部分標題被截斷）：字級加大到 14px、每分鐘 5px（30 分鐘的場次 150px 高）、欄寬 160px，讓標題、時間、講者在方塊內完整顯示（實測 4px／150px 時 HWDC 70 場仍有 10 場被截斷，5px／160px 為 0 場；使用者選定後者）。代價是時間軸變長、變寬，需要多捲動；手機上也可以用兩指縮放看全貌。
- 不做從網址自動抓：官網是伺服器端產生的頁面、沒有公開 JSON API，瀏覽器跨網域會被擋，要另架代理伺服器，不在本提案範圍。

**其他**
- `test.mjs`（預估）：用 node 跑的最小自檢，驗證「現在／下一場」判斷邏輯與官網文字解析。
- `README.md`：建立 Supabase 專案、執行 `setup.sql`、設定 Redirect URL、自己註冊後關閉公開註冊、閒置暫停的提醒。
- 時間一律以裝置本地時間判斷（現場在台灣，不另外處理時區）。

## 影響範圍
- 全新專案，不影響其他 repo。Supabase 只新增 `conferences` 一張表，不動專案內其他表。
- 需要你做的事：提供 Supabase 專案的 anon key；執行 `setup.sql`（加 `catalog` 欄位後要再跑一次）；在 Supabase Auth 設定 Redirect URL；用自己的 email 登入。登入需要收你的信，這幾步只能由你操作，我負責寫好步驟與 SQL。
- 部署會在你的 GitHub 建立新 repo 並開啟 Pages（免費方案需 public repo）。repo 裡只有程式碼和 anon key，不含你的議程資料。這一步實作時會先跟你確認 repo 名稱再執行。
- 頁面會從 jsdelivr CDN 載入固定版本的 supabase-js。
- Supabase 免費專案連續 7 天沒有請求會暫停：暫停期間只能看離線快取、不能編輯，需到 Supabase 後台恢復。
- 存檔是「整個研討會整列覆蓋」：兩台裝置同時編輯同一個研討會時，後存的會蓋掉先存的。只有你一個人用，先接受這個限制。
- 每次匯入會把整份官方議程存進該研討會那一列（HWDC 一天約 35 場、幾 KB），在免費方案額度內。
- 不做：輸入網址自動抓議程（需代理伺服器）、拖拉排序、非 iThome 格式網站的解析。之後需要再另開提案。
