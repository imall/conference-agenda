# shared-conferences

## 狀態
approved

## 類型
新功能

## 為什麼做
目前一個研討會（官方議程 `catalog` 和我挑的場次 `sessions`）存在同一列，RLS 只給建立者本人讀寫，所以別人登入後什麼都看不到。希望研討會內容由我統一建好、匯入官方議程，其他人登入後可以選研討會、挑自己要聽的場次，彼此的挑選互不影響。只有我能建立、編輯、刪除研討會和匯入官方議程（使用者決定）。

## 要改什麼

**資料（`setup.sql`，可重跑）**
- `conferences` 只放研討會本身：名稱、官網連結、`catalog`。RLS 改成：所有登入者都能讀；只有管理者能新增、修改、刪除。
- 新表 `admins`（`user_id`）：列在裡面的人就是管理者。登入者只讀得到自己那一列，前端靠這個判斷要不要顯示管理按鈕。管理者名單不寫 email，repo 是 public 的，不把 email 放進去。
- 新表 `picks`：一人一個研討會一列，欄位 `owner`（預設 `auth.uid()`）、`conference_id`（研討會刪除時一起刪）、`sessions`（格式同原本，jsonb 陣列）。`(owner, conference_id)` 唯一。RLS 只給本人讀寫刪。
- 搬遷分兩段，讓線上舊版網頁在新版部署前都能照常使用（HWDC 10/14–10/15 進行中，修訂新增）：
  - **第一段（任務 1）**，一個 DO 區塊，整段成功或整段不生效：
    1. `admins` 是空的時候，把現有研討會的 `owner` 設為管理者；還是空的（全新專案）就用最近一次登入的使用者。
    2. `conferences` 還有 `sessions` 欄位時：把每列非空的 `sessions` 複製到 `picks`（owner 照舊，`picks` 已有的那一列不覆蓋）。**不刪舊欄位**，舊版網頁照常讀寫它。
    3. 種子資料改成：沒有任何研討會、且已有管理者時，建立 HWDC 2026，那 5 場放進 `catalog`（不再放進個人挑選）。`test.mjs` 讀的種子文字格式不變。
  - **第二段（任務 4，新版部署並確認後）**：`setup.sql` 最後加上刪掉 `conferences.sessions` 欄位（`DROP COLUMN IF EXISTS`），你再跑一次 `setup.sql`。刪掉欄位是為了不讓其他人讀研討會時看到我的挑選；這時才打開註冊，所以兩段之間沒有其他人能讀到。欄位刪掉後，第一段的複製會自動跳過，重跑不會重複搬。
- 搬遷的權威資料：新版部署前是 `conferences.sessions`（舊版網頁），新版部署後是 `picks.sessions`。以「新版部署」為切換點。第一段到部署之間在舊版網頁上改的挑選**不會**帶到 `picks`（重跑不覆蓋已有的列）；這段期間需要改挑選，就在部署前請我清掉你的 `picks` 再跑一次第一段。

**畫面（`index.html`）**
- 讀取：同時讀 `conferences`、自己的 `picks`、自己是不是管理者。前端把自己的挑選放回每個研討會的 `sessions` 再顯示，所以「現在／下一場」、我的議程、挑選場次、撞場的顯示邏輯都不用改。離線快取也記住是否為管理者。
- 寫入：
  - 挑選場次、「＋ 場次」、編輯／刪除場次：寫進自己的 `picks`（沒有就新增，有就更新）。
  - 新增／編輯／刪除研討會、匯入官方議程：寫進 `conferences`，只有管理者看得到這三個按鈕（「＋ 研討會」「編輯研討會」「匯入官方議程」）。按鈕藏起來只是介面，真正擋住的是 RLS。
  - 刪除研討會的確認訊息改成提醒「所有人在這個研討會的挑選也會一起刪除」。
- 一般使用者的「編輯」模式只剩「＋ 場次」和每場的「編輯」，改的都是自己的挑選。
- 還沒有任何研討會時，一般使用者看到「還沒有任何研討會」。

**說明（`README.md`）**
- 第 5 步改成：保持開放註冊（Authentication > Sign In / Providers 的「Allow new users to sign up」要打開），並說明誰能看到什麼。
- 說明管理者怎麼決定、怎麼加第二個管理者（在 SQL Editor 對 `admins` 新增一列）。

## 影響範圍
- 檔案：`setup.sql`、`index.html`、`README.md`。`agenda.js`、`sw.js`、`test.mjs` 預估不用改。
- Supabase 資料：新增 `admins`、`picks` 兩張表；新版部署並確認你的挑選都在之後，才刪掉 `conferences.sessions` 欄位。**第一段執行前建議先在 Supabase 後台匯出 `conferences` 備份**（Table Editor > conferences > Export > CSV）。
- 第一段跑完後，本機預覽的新版和線上舊版用同一個 Supabase：本機挑選寫進 `picks`、線上挑選寫進舊欄位，兩邊互不影響，部署後以 `picks` 為準。
- 需要你做的事：在 SQL Editor 跑新的 `setup.sql`；在 Supabase 後台打開註冊；用第二個 email 測試一般使用者（Gmail 可以用 `你的帳號+test@gmail.com`，信會寄到同一個信箱）。
- 開放註冊後，任何知道網址的人都能註冊並看到研討會內容（官方議程本來就是公開的），但看不到別人挑了哪些場次，也改不了研討會。
- Supabase 內建的寄信服務每小時能寄的登入信很少（官方限制，確切數字以 Supabase 後台為準）。同一小時內很多人第一次登入時可能收不到信，要換自己的 SMTP 才能解除。少數朋友使用時先接受這個限制。
- 舊版網頁（手機上還沒重新整理的分頁）在欄位刪掉後存挑選會顯示「儲存失敗」，重新整理就會換成新版。不會悄悄丟資料。
- 同一台裝置換另一個帳號登入時，離線快取裡可能先閃過前一個帳號的挑選，載入完成後會換掉。裝置是個人在用，先不處理。
- 不做：多個研討會各自指定不同管理者、在網頁上管理管理者名單、自訂 SMTP。
